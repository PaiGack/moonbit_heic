## 项目简介

MoonHEIC 把 iPhone 等设备广泛使用的 HEIC 静态图，在 MoonBit 里从容器一路解到像素并输出 PNG / JPEG：ISOBMFF / HEIF 容器解析、HEVC NAL 与参数集、CABAC 算术解码与 I 帧重建、环路滤波、色彩转换、几何变换、图像编码、命令行工具，全部由 MoonBit 原生实现，不链接 libheif / FFmpeg 等 C 动态库。项目面向需要在浏览器、WASM 边缘运行时或纯 MoonBit 应用中读取 HEIC 的库作者、工具开发者与应用开发者，提供 `@heif.parse`、`primary_image`、`parse_access_unit`、`decode_i_frame`、`convert` 等可直接调用的 API，以及 `heic2png` / `heicinfo` 两个命令。

现有做法通常依赖平台原生解码库，或通过 FFI / 内嵌运行时跨语言调用：部署时要处理动态库、汇编优化与 ABI 差异，浏览器端尤其受限，跨语言边界的数据拷贝与校验也难以保证一致性。把解码器完整移植到 MoonBit，既能让 HEIC 在 wasm / wasm-gc 后端开箱可用（wasm-gc 产物约 408 KB），也是对语言本身的一次端到端压力测试。逐层对拍上游真值、独立 JS 转录复核和 CI 中的固件防漂移检查，使移植过程本身成为可回归、可定位、可继续优化的工程质量基线，也为日后用 `v128` 重写 SIMD、扩展 tiles / WPP 留出清晰入口。

## 核心功能范围

- **HEIF / ISOBMFF 容器（`heif/`，M1）**：走通 `ftyp` / `meta` / `hdlr` / `pitm` / `iinf`+`infe` / `iloc` / `iprp`(`ipco`+`ipma`) / `iref` / `idat`，`mdat` 只记偏移；解析 `hvcC`（含参数集字节）、`ispe`、`pixi`、`colr`/`nclx`、`prof`、`irot`/`imir`、`clap`、`auxC`；按 `pitm` 选主图，按 `thmb` / `auxl`+`auxC` / `grid`+`dimg` 识别缩略图、alpha 与派生图；遇到 essential 的未知属性标为 unsupported 而非假装能解，畸形与截断输入返回 `Invalid` / `Unsupported` 且不 trap。
- **HEVC 头解析（`hevc/`、`hevc/bitreader/`、`hevc/headers/`，M2）**：AnnexB 与 `hvcC` length-prefixed 分帧、MSB-first 位读取、VPS / SPS / PPS / slice segment header、`parse_access_unit` 装配 `AccessUnit` 并给出每片 `data_offset`；profile 双层检查只放行 Main（1）与 Main Still Picture（3）的 8bit 4:2:0，其余抛带字段值的 `UnsupportedProfile`。
- **I 帧解码内核（M3，10 个子包）**：179 上下文 CABAC 算术解码（Table 9-4 / 9-46 / 9-47 逐条对齐）、扫描表与逆变换基矩阵、反量化 / 2D 逆变换 / 35 种帧内预测、残差系数语法 7.3.8.11、去块 8.7.2 与 SAO 8.7.3、CTU 级语法元素 7.3.8.2~7.3.8.10、CTU 空间状态（6.5.2 / 6.4.1 / 8.6.1 / 8.4.4.2.2）、单块重建链路以及 CTU quadtree / TU / PU 语法主循环；`decode_i_frame` 输出 `Yuv420p8`。SAO syntax+apply、scaling list、PCM、transform skip、transquant bypass、`cu_chroma_qp_offset` 全部接进主循环与 decode 路径。
- **色彩与图像编排（`color/`、`image/`，M4）**：BT.601 / BT.709 / BT.2020 三套矩阵（由 `nclx` 的 `matrix_coefficients` 选择）、limited / full range、4:2:0 最邻近上采样、PQ / HLG 最简 SDR 映射、alpha 平面合成，整数定点实现；按 MIAF 7.3.6.7 顺序先 `clap` 裁剪、再 `irot`（0/90/180/270）与 `imir`。
- **自写编码器（`io/png/`、`io/jpeg/`，M4）**：PNG chunk 层支持 RGBA8 / RGBA16、可控 DEFLATE 级别、CRC-32、`iCCP` 原样携带 ICC；baseline JPEG 支持 RGB→YCbCr→8×8 DCT→质量可调量化→标准 Huffman 表、4:4:4 无色度子采样、`0xFF` 填充、APP2 ICC，透明像素合成到白底。
- **CLI 与批量转换（`cmd/`，M5）**：`convert` 纯逻辑管线（容器 → AU → YUV → RGBA → 编码文件）、`cli` 进程胶水、`heic2png` / `heicinfo` 命令、`bench` 四后端耗时驱动；参数表覆盖 `-o`、`-f`、`-q`、`--16bit`、`-j`（目录批量用 task group + semaphore 限并发，默认 4）；错误分类为 `Input` / `Unsupported` / `Decode`，退出码 **0 成功 / 1 输入不可读 / 2 不支持的 profile / 3 解码失败**，错误写 stderr 且干净退出。
- **分层对拍与差分工具（`tools/`）**：`tools/parity/dump.mjs` 报首个差异的结构化路径（如 `$.sps.pic_width_in_luma_samples`）或字节索引与十六进制窗口；11 个 golden 生成器、9 个独立 JS 转录 crosscheck、9 个 Go 导出测试（从上游真实解码器取真值）、12 个 HEIF 容器固件、21 个 HEIC 样本（含 9 个畸形）、14 帧整帧固件；`tools/e2e/` 用独立写的 JS BT.709 参考逐字节算 PSNR，并测四后端完整 `convert()` 墙钟耗时与产物体积。
- **CI（`.cnb.yml`）**：push 与 PR 各 9 个 stage——`moon check --deny-warn`、`moon test`、`moon info` 后 `.mbti` 无漂移、`moon fmt --check`、parity 自测、10 组 golden `--check` 与 crosscheck、e2e `--smoke`、M4 CLI 端到端自检；全仓 113 个 `.mbt` 文件，其中 36 个 `_test.mbt` 黑盒测试文件与 1 个 `_wbtest.mbt` 白盒测试文件。

## 预期验收产物

- `nrzhangsan/heic` 库（25 个单向依赖的包），`moon add` 后即可调用 `@heif.parse(Bytes)`、`HeifFile::primary_image()`、`item_payload()`、`@hevc.parse_access_unit()`、`@hevc/decode.decode_i_frame()`、`@cmd/convert.convert(Bytes, Options)`；`moon info` 生成的 25 份 `.mbti` 公开接口在 CI 中受防漂移检查。
- 两个可直接使用的命令 `heic2png`（单图 / 目录批量、PNG 8/16bit、质量可调 JPEG）与 `heicinfo`（元信息侦察），以及可复现的退出码矩阵：0 / 1 / 2 / 3 共 7 类场景全部实测通过。
- 与上游 Go 解码器的一致性证据：CABAC 8400 个 bin 逐位一致；recon 层 222000 个值、residual 层 122488 个值、loopfilter 层 126834 个值、syntax 层 1739 个值、geometry 层 14759 个值与上游真值零差异；scaling list 16384 个 factor 独立复核零差异；13 帧小 I 固件逐像素复现、14 帧端到端固件（含 4032×3024 大图）以 FNV-1a checksum + 64 探针逐样本对齐。
- 端到端产物与质量记录：真实 I 帧码流包成最小 HEIC → CLI 出 PNG，与独立 JS 参考逐字节比 PSNR，5 张固件中 4 张为 `inf` dB（完全相等），带量化噪声的 `qp_small.h265` 实测 **47.26 dB**，全部高于 45 dB 验收线；报告见 `tools/e2e/REPORT.md` 及 `run.mjs` 生成的机器可读 JSON。
- 差分测试工具与测试记录报告：`tools/parity/` 首个差异定位、`tools/*_golden.json` 与 12 份 MoonBit 侧 golden 表、`tools/e2e/` harness 自测、M4 CLI 自检；任一固件手改一个字节，CI 的 `--check` 即变红。
- 性能与体积基线：64×64 I 帧完整 `convert()`（不含进程启动，debug 构建）native ~6.3 ms、wasm ~5.7 ms、wasm-gc ~4.3 ms、js ~42 ms；产物体积 2 789 472 B / 688 797 B / 408 071 B / 731 784 B，由 `cmd/bench` 在四后端编译运行产出。
- 文档与合规说明：`README.mbt.md` 给出包结构、示例、支持 / 不支持清单（含拒绝位置与退出码）、开发命令；`LICENSE` 为 Apache-2.0，README 保留上游 MIT 版权声明并给出 HEVC 标准必要专利提示。
- 明确的范围边界（代码一律显式拒绝，不伪造像素）：仅单帧静态图、I 帧、8bit、4:2:0、HEVC Main / Main Still Picture、HEIF 容器、单 slice 单 tile 无 WPP；P / B 帧与运动补偿、10/12bit 与 Main 10 / RExt、4:2:2 / 4:4:4 / 4:0:0、grid 平铺、多 slice 拼接、dependent slice、tiles / WPP、编码器与 HEIC 视频序列、非 HEVC 的 HEIF 均返回 `DecodeError` / 退出码 2。

## 移植或参考说明

- 原项目名称：`gen2brain/h265`（纯 Go 的 HEVC 视频 / HEIC 图像编解码器；README 同时记录其镜像 `PaiHL/h265` 与更早的源头 `roticv/rust_h265`）
- 原项目链接：https://github.com/gen2brain/h265
- 原项目许可证：MIT License（上游版权声明随本移植在 `README.mbt.md` 中保留）
- 本项目许可证：Apache-2.0（见 `LICENSE`；与移植部分一起分发时上游 MIT 声明一并生效。HEVC / H.265 受专利池覆盖，本项目不授予任何专利权利，商用部署需自行取得许可）

与原项目相比，本项目做了以下简化和重新设计：

- **按里程碑拆包，而不是复刻 Go 的包结构**：25 个包按里程碑分层、依赖方向单向（容器与码流 → 解码内核 → 色彩与图像编码 → CLI），公开接口由 `.mbti` 固定并接入 CI；上游未导出函数改为可独立验收的公开内核（bitreader、cabac、dsp、recon、residual、loopfilter、syntax、geometry、reconstruct、ctu、decode）。
- **错误模型 MoonBit 化**：Go 的 panic / error 改为 `Result` 与具名错误（`HeifError`、`UnsupportedProfile`、`DecodeError`、`ConvertError`），不吞异常、不 trap；错误再映射到 CLI 的 0/1/2/3 退出码，让「不支持」与「解坏了」可区分。
- **锁定单线程子集，明确放弃并行与汇编**：只交付单 slice、单 tile、无 WPP 的 Main 8bit 4:2:0 纯 I 帧；上游 7242 行 SIMD 汇编与 tiles / WPP 并行不移植，后续可用 `v128` 重写。范围外能力保留兼容入口与清晰的拒绝原因，而非静默降级。
- **真值链独立重建**：用 9 个 Go 导出测试从上游真实解码器（`DecodeNAL + Flush`、`-tags noasm`）导出 golden，再写 9 个独立 JS 转录做 crosscheck，CI 用 `--check` 钉死固件与格式，避免「端口用自己的固件验自己」；`tools/e2e/reference.mjs` 也是独立于待测 `color/` 的参考实现。
- **输出层去 C 依赖**：PNG / JPEG 编码器全部用 MoonBit 自写，不依赖系统图像库；`preferred_target` 设为 `wasm`，解码内核在 native / wasm / wasm-gc / js 四后端均可编译，CLI 因 `@fs` / `@stdio` 的运行时边界只在 native / wasm 上真正可用。
- **以 MoonBit API + CLI + 标准图像文件为主要交付接口**：便于接入 Web、WASM、批处理和现有图像工具链，配套 README 示例、差分工具、端到端报告与 CI，使移植结果可独立复现与继续演进。

## 已知限制（申报边界）

- 解码单线程，`-j` 只并行多个独立文件，不加速单张图；无 SIMD，js 后端约为 native 的 6~7 倍耗时。
- 4032×3024 大图在 M3 固件中以 checksum 验收过，CI 冒烟只用 16×16，不重跑大图。
- PQ / HLG 只做 1000-nit 最简 SDR 映射，色度上采样只有最邻近；PNG 隔行 / 调色板、JPEG 色度子采样 / 渐进式不产出，EXIF 方向不处理（只认 `irot` / `imir`）。
- CI 容器没有 libheif 与相机原图，因此「外部对照」以上游 Go 解码器的 planar YUV 作权威真值做等价的逐像素 PSNR；与 `heif-convert` / iPhone 实拍的实机对照仍需在有该环境的机器上补测。
