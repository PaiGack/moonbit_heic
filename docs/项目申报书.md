# MoonHEIC 项目申报书

## 基本信息

- 项目名称：MoonHEIC：纯 MoonBit 的 HEVC / HEIC 解码器与图像转换工具链
- 参赛者：Pai2s
- 联系方式：GitHub @PaiGack
- 代码仓库链接：https://github.com/PaiGack/moonbit_heic
- 项目方向：MoonBit 图像编解码基础库 / 多媒体与 WebAssembly 基础设施
- 是否为移植项目：是

## 项目简介

MoonHEIC 把 iPhone 等设备广泛使用的 HEIC 静态图，在 MoonBit 里从容器一路解到像素并输出 PNG / JPEG：ISOBMFF / HEIF 容器解析、HEVC NAL 与参数集、CABAC 算术解码与 I 帧重建、环路滤波、色彩转换、几何变换、图像编码、命令行工具，全部由 MoonBit 原生实现，不链接 libheif / FFmpeg 等 C 动态库。项目面向需要在浏览器、WASM 边缘运行时或纯 MoonBit 应用中读取 HEIC 的库作者、工具开发者与应用开发者，提供 `@heif.parse`、`primary_image`、`parse_access_unit`、`decode_i_frame`、`convert` 等可直接调用的 API，以及 `heic2png` / `heicinfo` 两个命令。

现有做法通常依赖平台原生解码库，或通过 FFI / 内嵌运行时跨语言调用：部署时要处理动态库、汇编优化与 ABI 差异，浏览器端尤其受限，跨语言边界的数据拷贝与校验也难以保证一致性。把解码器完整移植到 MoonBit，既能让 HEIC 在 wasm / wasm-gc 后端开箱可用，也是对语言本身的一次端到端压力测试。逐层对拍上游真值、独立 JS 转录复核和 CI 中的固件防漂移检查，使移植过程本身成为可回归、可定位、可继续优化的工程质量基线，也为日后用 `v128` 重写 SIMD、扩展 tiles / WPP 留出清晰入口。

## 核心功能范围

- **HEIF / ISOBMFF 容器（`heif/`，M1）**：走通 `ftyp` / `meta` / `hdlr` / `pitm` / `iinf`+`infe` / `iloc` / `iprp`(`ipco`+`ipma`) / `iref` / `idat`，`mdat` 只记偏移；解析 `hvcC`（含参数集字节）、`ispe`、`pixi`、`colr`/`nclx`、`prof`、`irot`/`imir`、`clap`、`auxC`；按 `pitm` 选主图，按 `thmb` / `auxl`+`auxC` / `grid`+`dimg` 识别缩略图、alpha 与派生图；遇到 essential 的未知属性标为 unsupported 而非假装能解，畸形与截断输入返回 `Invalid` / `Unsupported` 且不 trap。
- **HEVC 头解析**：AnnexB 与 `hvcC` length-prefixed 分帧、MSB-first 位读取、VPS / SPS / PPS / slice segment header、`parse_access_unit` 装配 `AccessUnit` 并给出每片 `data_offset`；profile 双层检查只放行 Main（1）与 Main Still Picture（3）的 8bit 4:2:0。
- **I 帧解码内核**：179 上下文 CABAC 算术解码（Table 9-4 / 9-46 / 9-47 逐条对齐）、扫描表与逆变换基矩阵、反量化 / 2D 逆变换 / 35 种帧内预测、残差系数语法 7.3.8.11、去块 8.7.2 与 SAO 8.7.3、CTU 级语法元素 7.3.8.2~7.3.8.10、CTU 空间状态（6.5.2 / 6.4.1 / 8.6.1 / 8.4.4.2.2）、单块重建链路以及 CTU quadtree / TU / PU 语法主循环；`decode_i_frame` 输出 `Yuv420p8`。SAO syntax+apply、scaling list、PCM、transform skip、transquant bypass、`cu_chroma_qp_offset` 全部接进主循环与 decode 路径。
- **色彩与图像编排**：BT.601 / BT.709 / BT.2020 三套矩阵（由 `nclx` 的 `matrix_coefficients` 选择）、limited / full range、4:2:0 最邻近上采样、PQ / HLG 最简 SDR 映射、alpha 平面合成，整数定点实现；按 MIAF 7.3.6.7 顺序先 `clap` 裁剪、再 `irot`（0/90/180/270）与 `imir`。
- **自写编码器**：PNG chunk 层支持 RGBA8 / RGBA16、可控 DEFLATE 级别、CRC-32、`iCCP` 原样携带 ICC；baseline JPEG 支持 RGB→YCbCr→8×8 DCT→质量可调量化→标准 Huffman 表、4:4:4 无色度子采样、`0xFF` 填充、APP2 ICC，透明像素合成到白底。

## 预期验收产物

- `PaiGack/heic` 库，`moon add` 后即可在 MoonBit 项目中使用其 API。
- 与上游 Go 解码器的一致性证据：CABAC 8400 个 bin 逐位一致；recon 层 222000 个值、residual 层 122488 个值、loopfilter 层 126834 个值、syntax 层 1739 个值、geometry 层 14759 个值与上游真值零差异；scaling list 16384 个 factor 独立复核零差异；13 帧小 I 固件逐像素复现、14 帧端到端固件（含 4032×3024 大图）以 FNV-1a checksum + 64 探针逐样本对齐。
- 端到端产物与质量记录：真实 I 帧码流包成最小 HEIC → CLI 出 PNG，与独立 JS 参考逐字节比 PSNR。

## 移植或参考说明

- 原项目名称：`gen2brain/h265`（纯 Go 的 HEVC 视频 / HEIC 图像编解码器；README 同时记录其镜像 `PaiHL/h265` 与更早的源头 `roticv/rust_h265`）
- 原项目链接：https://github.com/gen2brain/h265
- 原项目许可证：MIT License（上游版权声明随本移植在 `README.mbt.md` 中保留）
- 本项目许可证：Apache-2.0（见 `LICENSE`；与移植部分一起分发时上游 MIT 声明一并生效。HEVC / H.265 受专利池覆盖，本项目不授予任何专利权利，商用部署需自行取得许可）

与原项目相比，本项目做了以下简化和重新设计：

- **按里程碑拆包，而不是复刻 Go 的包结构**：按模块分层、依赖方向单向（容器与码流 → 解码内核 → 色彩与图像编码 → CLI），公开接口由 `.mbti` 固定并接入 CI；上游未导出函数改为可独立验收的公开内核（bitreader、cabac、dsp、recon、residual、loopfilter、syntax、geometry、reconstruct、ctu、decode）。
- **错误模型 MoonBit 化**：Go 的 panic / error 改为 `Result` 与具名错误（`HeifError`、`UnsupportedProfile`、`DecodeError`、`ConvertError`），不吞异常、不 trap。
- **锁定单线程子集，明确放弃并行与汇编**：只交付单 slice、单 tile、无 WPP 的 Main 8bit 4:2:0 纯 I 帧；上游 7242 行 SIMD 汇编与 tiles / WPP 并行不移植，后续可用 `v128` 重写。
- **输出层去 C 依赖**：PNG / JPEG 编码器全部用 MoonBit 自写，不依赖系统图像库；`preferred_target` 设为 `wasm`，解码内核在 native / wasm / wasm-gc / js 四后端均可编译，CLI 因 `@fs` / `@stdio` 的运行时边界只在 native / wasm 上真正可用。
- **以 MoonBit API + CLI + 标准图像文件为主要交付接口**：便于接入 Web、WASM、批处理和现有图像工具链，配套 README 示例、差分工具、端到端报告与 CI，使移植结果可独立复现与继续演进。
